# TPS Gift Fund Demo - Project Overview

<!-- blueprint:source-hash 1ded89380b759d91e6941ce07dedbc1ef5e4f7124a2dc40c04e9b6ea2119966a -->

> A working demo of the TPS Gift Fund: guests give to a mum's fund, every gift becomes prepaid TPS credit, built to learn the mechanics before integrating them into TPS-CRM.

## Problem

The Postpartum Suite (TPS) wants friends and family to give TPS care as a gift. A mum (or an organiser using the mum's email) creates a fund page, guests give any amount with a message, and it all becomes prepaid credit for TPS services: gift credit, never cash, never a fundraiser or donation. This repo makes the mechanics visible (fee, Stripe confirmation, ledger balance, closing, expiry) so they can later be built into TPS-CRM.

## Users

All roles are simulated without sign-in.

- **Mum** - owns the fund; sees balance, expiry, every message and amount; tops up; requests to use credit.
- **Organiser** - creates the fund using the mum's email.
- **Guest** - gives by card with a message; chooses whether the amount shows publicly.
- **TPS admin** - sees all funds and records credit used.

## Usage model

- Demo only: a handful of test funds, no real people's data, Stripe test mode only.
- No sign-in by design: anyone with a link can open the mum page and admin screen. Never hold real data or live Stripe keys.
- Payment rules still hold: the fee is calculated on the server, credit is added only by the Stripe webhook, and a payment is never counted twice.

## Product rules

| Rule | Behavior |
| --- | --- |
| Minimum | £10 per gift or top-up, enforced on the server |
| Card fee | `fee = (amount + 0.20) / 0.985 - amount`, rounded **up** to the penny, added on top and shown before paying. £50 -> £50.97 total. |
| Guest amounts | Shown publicly only if the guest ticks show-amount; the mum always sees all |
| Top-ups | From £10, any time; never shown on the public page |
| Public total | Sum of paid guest gifts including hidden amounts; top-ups excluded |
| Closing | `close_date = due_date + 28 days`; no gifts or top-ups after it |
| Expiry | `expires_on = close_date + 12 months`; balance counts as £0 after it |
| Balance | Sum of ledger credits minus debits; never stored as its own number |
| Paid status | Only `checkout.session.completed` marks a contribution paid and writes the credit; repeat webhook calls are ignored; the thanks page never adds credit |
| Using credit | Nothing applied automatically. Requests capped at balance minus open requests. Treatments: credit off the listed price. Programmes: "Price agreed at consultation", mum picks the amount. Leftover credit keeps the same expiry. |
| Fund goes live | Immediately on creation |
| Refunds | Not offered |
| Dates | Closing and expiry computed on each page load from today or the demo date; no scheduled job |

## Features

In build-plan order; features 1-7 are done. The headline is the gift-to-credit loop (6 and 7).

1. **App scaffold** (done) - Next.js 16 App Router, React 19, TypeScript, Tailwind v4.
2. **Database foundation** (done) - Neon Postgres + Drizzle with the five tables below.
3. **Money and date rules** (done) - fee, minimum, close date, expiry and ledger balance in pence, in one place: the core algorithm.
4. **Create a fund** (done) - `/fund/new` creates the fund and slug and writes the "fund created" outbox email.
5. **Public fund page** (done) - total, goal bar, guest messages with hidden amounts respected, close date, share link, Contribute.
6. **Guest checkout** (done) - amount, message, show-amount, server-side fee, pending contribution, Stripe Checkout in test mode.
7. **Payment webhook** (done) - marks the contribution paid once, adds the credit entry, writes the guest receipt and "you've received a gift" to the outbox.
8. **Mum page** - `/fund/<slug>/me`: balance, expiry, every message and amount, top-up history.
9. **Mum top-ups** - same checkout and webhook path with `type = topup`, private to the mum.
10. **Use my credit** - choose a service and amount (capped), creates a credit request and an outbox email to TPS.
11. **Admin screen** - funds, balances, dates, contributions, open requests; record credit used (debit entry).
12. **Demo outbox and clock** - outbox page for every email; "pretend today is" date driving closing and expiry.
13. **Deploy to Vercel** - personal Vercel, Neon, Stripe test keys and webhook endpoint, then the demo walkthrough.

## Data model

Money is integer pence throughout. IDs are generated by the database.

### funds

- `id` (uuid, pk)
- `slug` (text, unique) - first name + due year-month, e.g. `sarah-202702`, random suffix if taken
- `mum_first_name` (text)
- `mum_email` (text)
- `created_by_email` (text) - organiser, or the mum herself
- `due_date` (date)
- `close_date` (date) - `due_date + 28 days`, stored at creation
- `goal_pence` (integer, nullable)
- `note` (text, nullable)
- `created_at` (timestamptz)
- Expiry is derived: `close_date + 12 months`. Open/closed/expired is derived from the current or demo date.

### contributions

- `id` (uuid, pk)
- `fund_id` (uuid, fk -> funds)
- `type` (enum `guest` | `topup`)
- `name`, `email` (text)
- `message` (text, nullable)
- `amount_pence` (integer) - what becomes credit
- `fee_pence` (integer) - card fee paid on top
- `show_amount` (boolean) - guests only; top-ups are always private
- `stripe_session_id` (text, unique, nullable) - set when the Checkout Session is created; the webhook finds the contribution by it
- `status` (enum `pending` | `paid`)
- `created_at` (timestamptz)

### credit_ledger

- `id` (uuid, pk)
- `fund_id` (uuid, fk -> funds)
- `entry` (enum `credit` | `debit`)
- `amount_pence` (integer, positive)
- `reason` (text) - e.g. guest gift, top-up, credit used
- `booking_reference` (text, nullable) - for debits
- `recorded_by` (text, nullable) - admin name for debits
- `created_at` (timestamptz)
- A credit is written only by the webhook, once per paid contribution. A debit is written only by the admin screen.

### credit_requests

- `id` (uuid, pk)
- `fund_id` (uuid, fk -> funds)
- `service` (text)
- `amount_requested_pence` (integer)
- `status` (enum `new` | `done`)
- `created_at` (timestamptz)

### outbox

- `id` (uuid, pk)
- `to` (text), `subject` (text), `body` (text)
- `created_at` (timestamptz)
- Demo stand-in for sent email: fund created, guest receipt, gift received, top-up receipt, credit-use request, credit used.

> Locked for later features: pence amounts, the ledger-only balance, and `stripe_session_id` as the webhook's lookup key.

## Tech stack

- **Next.js 16.4** (App Router, Cache Components on) - pages, server actions, webhook route
- **React 19.3, TypeScript (strict)** - UI and types
- **Tailwind CSS v4** - styling
- **Neon Postgres + Drizzle** - database and migrations, matching TPS-CRM
- **Stripe Checkout (test mode)** - two line items, `Gift to <name>'s fund` and `Card processing fee`; contribution id in session metadata; product wording "TPS gift credit"
- **No email provider** - outbox table and page instead

## Monetization

Not applicable to the demo. In production, gifts are prepaid credit (money owed in future services) and the card fee is passed to the payer.

## UI/UX

Simple and clear enough to demo the flow, using the spec prototype's wording where possible. Gift-credit language only. Fees shown before paying, expiry shown wherever credit is.

- `/fund/new` - create a fund
- `/fund/<slug>` - public fund page
- `/fund/<slug>/give` - guest checkout
- `/fund/<slug>/thanks` - thank-you screen
- `/fund/<slug>/me` - mum page, top-ups, Use my credit
- `/admin/funds` - admin screen
- Demo bar - links to the mum page, admin and outbox, plus the "pretend today is" date

## Deployment

- Personal Vercel account, temporary. Build with the default Next.js build.
- Env vars: `DATABASE_URL`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (see `.env.example`).
- Neon Postgres database; Stripe test-mode keys; Stripe webhook endpoint pointed at the Vercel deployment. Locally, the Stripe CLI forwards webhooks.
- Verify: `npm run verify` (typecheck, build), also run by GitHub Actions on pull requests.
- Demo walkthrough: create a fund, two guest gifts (one amount hidden), open the mum page, top up £10, request credit for a treatment and a programme, record credit used, check the outbox and balances, then move the demo date past close and expiry.
